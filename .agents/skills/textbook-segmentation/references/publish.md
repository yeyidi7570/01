# 重跑保护与 GitHub 归档

## 建候选版本

1. 查看现有三件套、Git 历史、该课 `02_segmentation_review/lesson_XXX/`、已确认内容与未提交工作。保存旧版本的提交 SHA、数据版本、对象数量、审核文件路径和哈希。必要时查看用户明确提供的外部反馈；本地浏览器草稿可由审核员先导出，有反馈可能但无法获取时说明。默认复用完整有效成果，缺文件先判定可复用程度。
2. 以临时目录制作候选版。已有有效切割只升 UI 时保留数据、版本和 ID。已有内容需要重跑时，保留旧三件套的可追溯提交；未提交的旧稿用独立备份保留并确认归属。不能静默覆盖人工修改、原始审核 JSON 或后续已验证数据。
3. `scripts/lesson.py compare` 对照 ID 后再人工对照源页、锚点、类型、内容和归属。未变对象保留 ID；变更、拆分、合并、删除或歧义对象记录旧新 ID、改变类别、理由和复核方式。必要时更新数据版本。旧反馈原件保留；不兼容的反馈由人工决策，禁止重用 ID 指向另一道题或绕过审核导入校验。存在冲突、审核覆盖不明或人工修正将被替换时，保留候选与备份并请求对应决策。
4. 发布前再次核对旧版和反馈哈希，防止另一人更新。列出新旧差异与保留方式。发布目录只替换经过确认的三件套，其他版本来源及反馈目录保持可追溯。

## 单课发布

- 校验真实页边界、Task/Note/Other、子题、Badge、阅读顺序、公式表格、视觉关系、跨页、OCR 证据和教学关联。校验三件套的 Lesson ID、对象集、原文、切割区域、关系及初始状态完全一致。运行静态检查和 [断网实测](review.md)。
- 教学关联规则变更时，先只读盘点历史版本。按指定课次归档修订，保留原数据和审核记录。历史检查的兼容选项仅用于查阅旧版，新修订按现行规则验证。
- 更新书 README 中该课课号、真实标题、PDF 与印刷范围、Module/Note 数量、OCR 建议数、需人工复核的问题、文件和提交状态。确有交付才记 `segmentation_completed`，内容保持 `pending_review`。全册通过同一逐课门槛后才汇总全册。
- 核对 `.gitignore`、文件大小和 diff。扫描资源在一个页面内按资源 ID 共用，不重复内嵌。需要优化时保留审阅清晰度及完整教材区域；若超过 GitHub 限制，报告具体文件和大小。只暂存本课三文件、书 README 和本次必要的共享工具，提交后非强推推送当前对应远程分支。遇到他人更新，先取远程并核对冲突，禁止强推。
- 核对远程分支 SHA 以及 GitHub 文件树或 API 上的三个路径和内容。推送或测试受阻如实区分远程未交付、局部验证和本地候选。生成失败时不造空 JSON 或 HTML。
- 第一轮原始审核记录在 `02_segmentation_review/lesson_XXX/` 逐人保存；处理冲突和复核后的结果才进入 `03_verified_content/`。下一轮标签进入 `04_semantic_labels/` 及 `05_labels_review/`；完成两轮及必需修正才进入 `06_final/`。

## 根据人工提交修订

- 将原始导出按编号原字节保存为 `02_segmentation_review/lesson_XXX/submissions/review_001_original.json`。验证教材、Lesson、版本和记录 ID，对照对象类型、原值及来源位置。基于有效记录统计通过、有问题、无法判断和未审核，保留已被后续记录取代的历史。
- 将修订的三件套与 `change_log.md` 保存于对应的 `revision_1/`、`revision_2/` 等目录。修订编号按课从 1 递增，不补零。保留初始三件套与过往修订。记录有证据的改动、保留记录、未映射反馈及仍需复核的对象。
- 只有可证明内容等同的对象可沿用旧通过记录。容器通过只作为历史依据，已经改动的内容回到未审核。已处理的旧问题保留原记录，同时注明当前修订仍待复核。
- 批量应用已确认规则并按用户要求更新初始切割时，对内容有变更的课次记录旧版本及等同对象，允许导入旧版审核。已有原件按原字节归档。尚无提交的课次可只保存版本映射，并将已处理记录列表留空。仅升级审核页的课次沿用教材数据与版本。
